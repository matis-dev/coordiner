# Changelog

Newest entry first. The **Current state** section describes the extension as it is now, not how it got here.

## Current state (last synced 2026-10-27)

- **Commands:** `Coordiner: Check Environment`, `Coordiner: Run Story…` (runs the Story template), `Coordiner: Start…` (a quick pick of templates, single skills and your chains, with the same Run checks as the editor), `Coordiner: Open Chains`, `Coordiner: Stop Run`; a Run view in the activity bar lists each step with its tier, model, effort and status, with ▶ (Start…) and the chains editor in its title bar. Under the running step it lists that turn's background processes (shell commands, Monitors, subagents) with their latest progress line, through `plain()` and clipped to 120; **Stop Process** (inline, or the context menu for the keyboard) stops one, acts only on an id in the live list, and logs the task's kind and id, never its description. The list clears when the turn ends.
- **Build and packaging:** `pnpm build` runs `build.ts`, which bundles every dependency into `dist/` with esbuild (only `vscode` is external); the extension and the four modules the chains webview imports from `dist/` stay entry points. The `.vsix` comes from `pnpm dlx @vscode/vsce@4.0.0 package --no-dependencies` and carries no `node_modules`; `src/bundle.test.ts` fails if `dist/` would import anything but `vscode` and Node builtins. `pnpm audit` reads the lockfile only: the Agent SDK's `sdk.mjs` inlines its own zod (4.5.4 in 0.3.292), which ships in `dist/extension.js` unseen by it (profile §Security, accepted risks).
- **Claude Code:** sessions run the `claude` you installed: `coordiner.claudePath`, else the first `claude` on the sessions' PATH, else `~/.local/bin/claude`, else the binary the Claude Code editor extension bundles (`resources/native-binary/claude` in its current folder, so an update of that extension does not break it). Check Environment checks it first and runs no session without it; Run refuses before asking for input, and the chains palette shows the same message naming the setting.
- **Packaging and identity:** publisher `matis-dev`, MIT license, repository, issue and keyword links; `.vscodeignore` trims the packaged extension down to `dist/**`, `media/**` and documentation. Marketplace icon (`media/icon.png`, 512×512) and activity bar glyph (`media/coordiner.svg`, 24×24 `currentColor`) share the modern Kammerdiener motif: tuxedo, bowtie and targeting HUD monocle.
- **Chains:** a chain is a list of sessions, each a row of skill cards (`skill`, `args`, `label`, `pause`, optional `next`, `model` and `effort`). Every session is a fresh conversation. Four read-only templates ship, named after what you bring: Story, Idea (brainstorming → planning → implementing), Bug (debugging alone, which writes the fix itself) and New project (kickoff → planning → implementing). Six single-skill templates run one m-skills command in one session and ask only for a run name: Kickoff and Onboard (both pause for you), Security audit, UI audit, Accessibility audit and Docs audit. A template is duplicated to edit, and your own chains are saved in `chains.json` in the extension's global storage, never in a repo. A placeholder in a card's arguments sets what Run asks for: `{{story}}` a backlog story or a typed one, `{{idea}}` and `{{bug}}` a typed answer. A chain uses one kind at most (Run refuses more); a chain with none asks only for a run name.
- **Model and effort:** each card in your own chains has a **Model** select (**By tier**, or one of the models the session lists through `supportedModels()`, stored as the id it resolves to) and an **Effort** select (the levels the card's model takes; on By tier, only those all three tier models take). A pinned model runs every turn of the card, loop turns and the reminder included, and `NEXT <tier>` then only picks the tier of the card after it. A stored model or effort the session does not offer stays selected and marked, and Run is refused before the worktree. If the models cannot be listed, nothing is refused, a pinned model shows as stored, and the session's own model check still guards the turn. `model` must match `MODEL` and `effort` be one of `EFFORTS` (`src/chains.ts`).
- **Chains editor:** a webview (`Coordiner: Open Chains`) with templates, single skills and saved chains in a full-height rail on the left and the selected chain's sessions on the right, a "fresh context" divider between sessions. Cards are numbered as stations in each lane, in a grid whose columns line up from one session to the next. The accent colour is the theme's link colour (`--vscode-textLink-foreground`, falling back to `focusBorder`); the focus ring stays on `focusBorder`. Cards are added from the skills the open folder's Claude Code session offers (listed once per window without a model turn; m-skills first), moved with arrow buttons or Alt+←/→, and edited in place; every change is saved at once. Each chain says what it starts from; a placeholder shows as a chip with what Run will put there, and an editable chain explains the three placeholders. A disabled Run says why. The palette keeps the skill you picked when the editor re-renders. The editor stops at the limits a stored chain holds (30 skills a session, 20 sessions, 20,000 characters of arguments, 100 of name): **Add** and **Add a session** stay focusable but turn off with the reason shown. A `chains.json` that cannot be read is set aside as `chains.json.bak-<time>` and the editor says so; a change that is refused or cannot be written puts the editor back on the saved chains, and each one is announced, even when the reason repeats.
- **Run:** asks for the chain's input. A story is picked from a Markdown backlog file (`## Story N: …` / `### Slice N: …` headings) or typed via **Type a story…**; an idea or a bug is typed. A typed answer suggests the run name (its slug, or an empty name when it has no letter or digit in `[a-z0-9]`), which you can change; a picked story is named by its heading. The input is capped at 20,000 characters (heading and body together for a picked story). A chain without a placeholder asks only for a name. A next chain started from the chat after a run (**Start the next chain here**) skips the repository check, the input and the setup: its input is the last reply of the run before, and it runs in that run's worktree, after a modal confirm. First, a folder that is not a git repository, or one with no commits yet, is offered `git init` and a first commit in modals: an empty commit, or every file `.gitignore` lets through, listed by name before it is committed; more than 200 such files are refused, and so is a folder git cannot open (git missing, `safe.directory`), with git's message in the output. A modal confirm lists each session's cards, then a worktree is created at `<repo>.coordiner/<slug>` on branch `coordiner/<slug>` from `HEAD`, and the lockfile-derived install command runs in it. One run at a time: the slot is held from the moment Run is pressed, so a second Run is refused while the first is still asking for its input or installing.
- **Card semantics:** a "once" card takes one turn; `NEXT <tier>` moves to the next card on that tier, `DONE` moves on at the card's own tier. `NEXT` on the last card of a session ends the card as `DONE` does (a kickoff names the planning after it, a step the session does not have). The implementing card is a "loop": it continues on each `NEXT` (tier stops: Heavy/Standard/Light → strong/medium/weak) until `DONE`. A review's `DONE` skips the loop cards after it. A card that pauses for the user (brainstorming, debugging, kickoff, onboard), or one the user paused, talks with them in the run's chat: after each turn it waits, each message is another turn, and **Continue** applies the latest status line it gave (a pausing card that gave none is done). Only unattended turns count toward the 20-turn cap.
- **Story template:** session 1 is `planning-architect` → `implementing-architect`; session 2 starts with new files marked intent-to-add (literal pathspecs, cap 200), then `code-review-architect-uncommitted` → `implementing-architect fix the findings` → `rolling-history`. The commit brief is shown in the Coordiner output; nothing is committed.
- **Run chat:** a strip under the chain's detail column (the rail keeps the full height), tied to the run rather than to the selected chain (`media/chat.js`, decisions in `src/chat-logic.ts`, state in `src/talk.ts`, transcript in `src/transcript.ts`, its wiring to the editor and the journal in `src/run-chat.ts`). A divider above it (a focusable separator: drag, or ↑/↓/Home/End) sets its height, 15–80% of the window, remembered in the webview's state (on narrow widths, where the rail stacks above, the chat shrinks to the space left); **Hide chat** folds it to its heading. It shows assistant text and tool calls as plain text, your messages and answers, and a divider between sessions, keeping the newest 1,000 entries (on the page as in the extension) with one note at the top once older ones are dropped; the running card is marked in its lane. **Send** queues a message in front of the next turn's prompt, with its destination shown and **Withdraw**; **Pause after this turn** makes an unattended card wait; a skill's AskUserQuestion during a pause is answered in a form (offered labels or Other), which takes focus when focus was in the chat (a lone question is then not also announced; a set of several still announces its count); **Stop run** stops it. A pause or question while the editor is closed opens it without taking focus, with a notification; an open question has no time limit. Queued messages left when the run ends go back to the message box. When the run ends, the transcript gets one line saying how (done, nothing to review, halted with its reason, failed, stopped or refused) and the chat stays open on the run's last session: each message is a turn that resumes it, on its model and effort, with `AFTER_NOTE` (no status line) and the paused-turn tool rules, and each turn holds the run slot, so a new run waits for it. A failed turn is shown in the transcript and the chat stays open. **Stop run** reads **End chat**, Pause and Continue are gone, and **Copy resume command** (`cd <worktree> && claude --resume <id>`, built in the extension) and **Start the next chain here** appear. The chat ends when you end it or confirm a new run. While a card waits, a line under the status counts down how long the prompt cache stays warm (one hour or five minutes, read from what each response wrote to the cache; five minutes assumed, and said, until a response shows it), worked out from the clock so a sleep does not skew it, and its expiry is announced once. Paused turns get `INTERACTIVE_NOTE` instead of `UNATTENDED_NOTE`.
- **Stops:** a halt or failure prints the `claude --resume` line for the session; a stop after the first session also lists the card prompts left to run by hand, from the card that stopped. A run whose review session finds no changed file ends as "nothing to review". A finished run puts its last card's final message in the output, headed "Commit brief" when that card is rolling-history and "Result" otherwise. When the worktree is left unchanged, the output prints `git worktree remove` and `git branch -D` for it, quoted and ready to paste (none when a path holds a control character); Coordiner never runs them.
- **Git guard:** every session carries coordiner's own PreToolUse hook on Bash (`src/guard.ts`): git writes (the plumbing that stages, commits or overwrites files included, and a branch's `-f` / `-t` / `-u` / `--no-track` wherever it sits among the flags), `send-email`, `imap-send` and `svn dcommit`, `--no-verify` / `--no-gpg-sign` and publishing `gh` commands are denied whichever skills the chain uses, and so is anything that can define a git alias for the command: an alias or include set with `-c` / `--config-env`, any `git config` other than a read, and a `GIT_CONFIG*=` assignment. An unreadable command or a hook error is a denial. Denials are logged without the command text. It scans the command text, so it stops accidental writes, not a determined session (a branch named after another flag, a script file, a command built at run time, or an alias in your own git config gets past it); auto mode is the layer behind it.
- **Unattended rules:** permission mode `auto`, any other tool is denied and logged by name and input keys, never input values; questions take the Recommended option and are logged (in a paused turn they go to the user instead; every other tool is still decided as unattended). A session that ends `success` but flagged as an error (an API error, an outdated `claude`) fails the turn with the text it gave: "the session failed: …". A turn is refused if a skill the chain uses is missing from the session, if a chain using m-skills reports an m-skills load error, or if the model differs from the one requested; each session is capped at 20 turns. m-skills is recommended, not required; Check Environment reports whether it is installed without failing on its absence.
- **Journal:** one JSONL file per run under the extension's global storage (`journal/<slug>-<UTC stamp>.jsonl`), never inside the worktree; the first record names the chain, and each `step-started` record carries the step's model and, when set, its effort. Your chat messages (`you`) and answers (`answer`) are recorded with the card they went to.

## 2026-10-25 — feat: Offer git init and a first commit when a run's folder has no repository or no commits

- **Repo check:** `inspectRepo` (`src/worktree.ts`) returns a `RepoCheck` instead of throwing: `ready`, `no-repo`, `no-commits` or `failed`. `no-repo` only when `git rev-parse --show-toplevel`, run with `LC_ALL=C` so the message stays English, says "not a git repository"; any other failure (git missing, a repository git will not open under `safe.directory`) is `failed` with git's message, and is never offered `git init`. A `git status` failure after the repository is found still throws.
- **Setting the repo up:** `setUpRepo(folder, { exec, ask, log })` (new) runs the flow and asks through `ask` before each write. `no-repo` asks `init`, then `initRepo` runs `git init`. `no-commits` lists the files with `uncommitted`; more than `MAX_NEW_FILES` (200) is refused without asking. With files it asks `commit-files` (always, even after `git init` was agreed); with none it asks `empty-commit` only when `git init` was not just agreed. `firstCommit` runs `git add --all` (only with files), then `git commit --allow-empty -m "Initial commit"`. Each git step returns a `GitStep`, and a failure comes back as `{ kind: "failed", reason, detail }`, with the identity hint for a failed commit.
- **The file list:** `uncommitted` reads `git ls-files --cached --others --exclude-standard -z`, so the dialog shows names as git wrote them (no status codes, no C-quoting), and returns `files`, `too-many` or `failed`. A listing that overflows exec's output buffer (`ERR_CHILD_PROCESS_STDIO_MAXBUFFER`, 1 MiB by default) is far past the cap and is reported as `too-many`.
- **The modals:** `askSetup` (`src/extension.ts`) renders the three prompts as modals that agree only through their button (**Initialize git**, **Make first commit**, **Commit N files**, the last listing the first 10 names through `plain()`). `readyRepo` writes git's detail to the Coordiner output and shows the written reason with "See the Coordiner output."; `startRun` calls it where it called `inspectRepo`.

Per-skill behaviour (kind `once`/`loop`, tier, label, `next` prompt, `doneSkipsLoops`) lives in `SKILL_DEFAULTS` in `src/chains.ts`; any skill not in it is a "once" card on the medium tier. `fillStory` substitutes `{{story}}` and keeps the 20,000-character cap. A session whose first card is the uncommitted review triggers `prepareReview`, so the intent-to-add step follows the chain rather than a fixed "session 2".
- **Outcome shape:** `beforeReview` is replaced by `at: { session, card }` on `halted` / `failed`. `remainingCommands(chain, outcome)` lists the card prompts from the stopped card onward for a stop after session 1, and nothing for a stop inside session 1 (taken over with `claude --resume`). `JournalRecord` `run-started` gained `chain`, so the journal format changed.
- **Chain storage:** `Chain` / `Card` in `src/chains.ts`, with `parseChains` / `serializeChains` (`version: 1`). Parsing rebuilds each field into a fresh object, so unknown keys, including `__proto__`, never survive; skill names must match `^[A-Za-z0-9:_.-]{1,100}$`; template ids are reserved; limits of 20 sessions, 30 cards, 20,000 characters of args. `src/extension.ts` writes through a temp file and rename, sets a bad file aside as `chains.json.bak-<time>`, and refuses to save while an unreadable file could not be moved aside.
- **Skill discovery:** `listCommands` (`src/session.ts`) opens an SDK query whose prompt stream never sends a message, reads `supportedCommands()` from the initialize answer and aborts the session, so no model turn is spent (60-second timeout). `palette` (`src/skills.ts`) lists m-skills first, then the rest alphabetically.
- **Skill checks:** `runTurn` takes `requiredCommands` and `pluginProblem(init, required)` refuses a turn when a needed skill is absent; the m-skills load-error check applies only to chains that use m-skills. `REQUIRED_COMMANDS` now only defines "m-skills installed" for the editor and Check Environment.
- **Git guard:** `src/guard.ts` ports the rules of the m-skills `guard-mutations.sh` and `guard-outward.sh` into a PreToolUse hook that `runTurn` attaches to every session, because the plugin's own hook is no longer guaranteed to be loaded. It scans the whole command string with a lookbehind (so `/usr/bin/git` matches without a quadratic scan), allows the listing forms of `branch`, `tag`, `remote`, `stash` and `worktree`, and fails closed. Known gaps: a quoted mention such as `echo "git commit"` is denied; a command built at run time (`g=git; $g commit`) is not caught.
- **Webview:** the editor is plain DOM (`media/editor.js`, `media/editor.css`, native elements, `--vscode-*` variables only). `src/editor-html.ts` builds the page with a nonce CSP; `src/editor-protocol.ts` accepts only messages with an exact key set per type and rebuilds a `save` payload through `parseChain`; the m-skills link is a constant. Decisions (why Run is disabled, missing-skill flag, focus after a move or remove, Alt+arrow) live in `src/editor-logic.ts` and edits in `src/chain-edit.ts`, so `media/editor.js` only builds the DOM; `chains.ts`, `chain-edit.ts` and `editor-logic.ts` also load in the webview from `dist/`, so they import nothing at runtime beyond each other.
- **Tests:** webview DOM tests run the real `media/editor.js` in jsdom (`src/editor-dom.test.ts`); `jsdom` and `@types/jsdom` joined the exact-pinned dev dependencies, and `pnpm coverage` now includes `media/**/*.js`.
- **Docs and prompts:** `UNATTENDED_NOTE` says "a chain of skills" and tells any other skill to end with `COORDINER: DONE`. README prerequisites now call m-skills recommended, the pnpm prerequisite reads pnpm 12 to match `packageManager`, and a "Build and run a chain" section was added. Check Environment reports m-skills as information only.
- **Gates:** not run in this session; this entry records the diff.
- **Why it matters:** the story flow is now one template among several, so you can build and run your own chains of skills, with the no-commit and no-publish promise enforced by coordiner itself rather than by whichever plugin happens to be installed.
- **Affected:** `src/chains.ts`, `src/chain-edit.ts`, `src/run.ts`, `src/session.ts`, `src/skills.ts`, `src/guard.ts`, `src/protocol.ts`, `src/environment.ts`, `src/journal.ts`, `src/extension.ts`, `src/editor-html.ts`, `src/editor-logic.ts`, `src/editor-protocol.ts`, `media/editor.js`, `media/editor.css`, `package.json`, `pnpm-lock.yaml`, `README.md`, `.claude/PROJECT-PROFILE.md`.

## 2026-10-10 — feat: Session two and the run journal (slice 2)

- `runStorySession` became `runSession(script, deps)`, driven by a `Script` (`open` turn, `work` loop on `NEXT`, optional `close` turn on `DONE`). `sessionOne(story)` is plan → implement; `SESSION_TWO` is review → fix → history. A `NEXT` in the closing turn counts as a missing status line (one reminder, then halt).
- `runStory` runs session 1, then `prepareReview`, then session 2 as a **fresh** session (never a resume) so the reviewer does not share the author's context. Step numbers continue across both sessions.
- `prepareReview` (`src/worktree.ts`): `git status --porcelain` → `no-changes` on a clean tree; otherwise NUL-separated `ls-files --others --exclude-standard` and `git --literal-pathspecs add --intent-to-add -- …`, so new files appear in `git diff HEAD` without staging their content. More than 200 new files halts the run (usually a missing `.gitignore` entry). `--literal-pathspecs` stops a model-chosen name like `:!src/x.ts` from excluding another file from the review.
- `Outcome`: `done` carries the commit brief text (status line stripped by `withoutStatus`); new `no-changes`; `halted` carries `sessionId`; a halt or failure before the review sets `beforeReview`. `remainingCommands(outcome, labels)` lists what is left to run by hand.
- `UNATTENDED_NOTE` tells the review, fix and history phases how to end.
- Journal (`src/journal.ts`): `createJournal` writes one JSON line per record in call order; a failed write is reported once and never stops the run.
- **Why it matters:** a story now runs unattended all the way to a reviewed, fixed change and a commit brief, and every run leaves a record you can read afterwards.
- **Affected:** `src/run.ts`, `src/protocol.ts`, `src/worktree.ts`, `src/journal.ts`, `src/extension.ts`, `.claude/PROJECT-PROFILE.md`.
