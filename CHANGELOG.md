# Changelog

Newest entry first. The **Current state** section describes the extension as it is now, not how it got here.

## Current state (last synced 2026-10-23)

- **Commands:** `Coordiner: Check Environment`, `Coordiner: Run Story…` (runs the Story template), `Coordiner: Open Chains`, `Coordiner: Stop Run`; a Run view in the activity bar lists each step with its tier, model and status, with a button in its title bar for the chains editor.
- **Build and packaging:** `pnpm build` runs `build.ts`, which bundles every dependency into `dist/` with esbuild (only `vscode` is external); the extension and the four modules the chains webview imports from `dist/` stay entry points. The `.vsix` comes from `pnpm dlx @vscode/vsce@4.0.0 package --no-dependencies` and carries no `node_modules`; `src/bundle.test.ts` fails if `dist/` would import anything but `vscode` and Node builtins.
- **Claude Code:** sessions run the `claude` you installed: `coordiner.claudePath`, else the first `claude` on the sessions' PATH, else `~/.local/bin/claude`. Check Environment checks it first and runs no session without it; Run refuses before asking for input, and the chains palette shows the same message naming the setting.
- **Packaging and identity:** publisher `matis-dev`, MIT license, repository, issue and keyword links; `.vscodeignore` trims the packaged extension down to `dist/**`, `media/**` and documentation. Marketplace icon (`media/icon.png`, 512×512) and activity bar glyph (`media/coordiner.svg`, 24×24 `currentColor`) share the modern Kammerdiener motif: tuxedo, bowtie and targeting HUD monocle.
- **Chains:** a chain is a list of sessions, each a row of skill cards (`skill`, `args`, `label`, `pause`, optional `next`). Every session is a fresh conversation. Four read-only templates ship, named after what you bring: Story, Idea (brainstorming → planning → implementing), Bug (debugging alone, which writes the fix itself) and New project (kickoff → planning → implementing); a template is duplicated to edit, and your own chains are saved in `chains.json` in the extension's global storage, never in a repo. A placeholder in a card's arguments sets what Run asks for: `{{story}}` a backlog story or a typed one, `{{idea}}` and `{{bug}}` a typed answer. A chain uses one kind at most (Run refuses more); a chain with none asks only for a run name.
- **Chains editor:** a webview (`Coordiner: Open Chains`) with templates and saved chains in a full-height rail on the left and the selected chain's sessions on the right, a "fresh context" divider between sessions. Cards are numbered as stations in each lane, in a grid whose columns line up from one session to the next. The accent colour is the theme's link colour (`--vscode-textLink-foreground`, falling back to `focusBorder`); the focus ring stays on `focusBorder`. Cards are added from the skills the open folder's Claude Code session offers (listed once per window without a model turn; m-skills first), moved with arrow buttons or Alt+←/→, and edited in place; every change is saved at once. Each chain says what it starts from; a placeholder shows as a chip with what Run will put there, and an editable chain explains the three placeholders. A disabled Run says why. The palette keeps the skill you picked when the editor re-renders. The editor stops at the limits a stored chain holds (30 skills a session, 20 sessions, 20,000 characters of arguments, 100 of name): **Add** and **Add a session** stay focusable but turn off with the reason shown. A `chains.json` that cannot be read is set aside as `chains.json.bak-<time>` and the editor says so; a change that is refused or cannot be written puts the editor back on the saved chains, and each one is announced, even when the reason repeats.
- **Run:** asks for the chain's input. A story is picked from a Markdown backlog file (`## Story N: …` / `### Slice N: …` headings) or typed via **Type a story…**; an idea or a bug is typed. A typed answer suggests the run name (its slug, or an empty name when it has no letter or digit in `[a-z0-9]`), which you can change; a picked story is named by its heading. The input is capped at 20,000 characters (heading and body together for a picked story). A chain without a placeholder asks only for a name. A modal confirm lists each session's cards, then a worktree is created at `<repo>.coordiner/<slug>` on branch `coordiner/<slug>` from `HEAD`, and the lockfile-derived install command runs in it. One run at a time: the slot is held from the moment Run is pressed, so a second Run is refused while the first is still asking for its input or installing.
- **Card semantics:** a "once" card takes one turn; `NEXT <tier>` moves to the next card on that tier, `DONE` moves on at the card's own tier. The implementing card is a "loop": it continues on each `NEXT` (tier stops: Heavy/Standard/Light → strong/medium/weak) until `DONE`. A review's `DONE` skips the loop cards after it. A card that pauses for the user (brainstorming, debugging, kickoff), or one the user paused, talks with them in the run's chat: after each turn it waits, each message is another turn, and **Continue** applies the latest status line it gave (a pausing card that gave none is done). Only unattended turns count toward the 20-turn cap.
- **Story template:** session 1 is `planning-architect` → `implementing-architect`; session 2 starts with new files marked intent-to-add (literal pathspecs, cap 200), then `code-review-architect-uncommitted` → `implementing-architect fix the findings` → `rolling-history`. The commit brief is shown in the Coordiner output; nothing is committed.
- **Run chat:** a strip under the chain's detail column (the rail keeps the full height), tied to the run rather than to the selected chain (`media/chat.js`, decisions in `src/chat-logic.ts`, state in `src/talk.ts`, transcript in `src/transcript.ts`, its wiring to the editor and the journal in `src/run-chat.ts`). A divider above it (a focusable separator: drag, or ↑/↓/Home/End) sets its height, 15–80% of the window, remembered in the webview's state (on narrow widths, where the rail stacks above, the chat shrinks to the space left); **Hide chat** folds it to its heading. It shows assistant text and tool calls as plain text, your messages and answers, and a divider between sessions, keeping the newest 1,000 entries (on the page as in the extension) with one note at the top once older ones are dropped; the running card is marked in its lane. **Send** queues a message in front of the next turn's prompt, with its destination shown and **Withdraw**; **Pause after this turn** makes an unattended card wait; a skill's AskUserQuestion during a pause is answered in a form (offered labels or Other), which takes focus when focus was in the chat (a lone question is then not also announced; a set of several still announces its count); **Stop run** stops it. A pause or question while the editor is closed opens it without taking focus, with a notification; an open question has no time limit. Queued messages left when the run ends go back to the message box. Paused turns get `INTERACTIVE_NOTE` instead of `UNATTENDED_NOTE`.
- **Stops:** a halt or failure prints the `claude --resume` line for the session; a stop after the first session also lists the card prompts left to run by hand, from the card that stopped. A run whose review session finds no changed file ends as "nothing to review".
- **Git guard:** every session carries coordiner's own PreToolUse hook on Bash (`src/guard.ts`): git writes (the plumbing that stages, commits or overwrites files included, and a branch's `-f` / `-t` / `-u` / `--no-track` wherever it sits among the flags), `send-email`, `imap-send` and `svn dcommit`, `--no-verify` / `--no-gpg-sign` and publishing `gh` commands are denied whichever skills the chain uses, and so is anything that can define a git alias for the command: an alias or include set with `-c` / `--config-env`, any `git config` other than a read, and a `GIT_CONFIG*=` assignment. An unreadable command or a hook error is a denial. Denials are logged without the command text. It scans the command text, so it stops accidental writes, not a determined session (a branch named after another flag, a script file, a command built at run time, or an alias in your own git config gets past it); auto mode is the layer behind it.
- **Unattended rules:** permission mode `auto`, any other tool is denied and logged by name and input keys, never input values; questions take the Recommended option and are logged (in a paused turn they go to the user instead; every other tool is still decided as unattended). A turn is refused if a skill the chain uses is missing from the session, if a chain using m-skills reports an m-skills load error, or if the model differs from the one requested; each session is capped at 20 turns. m-skills is recommended, not required; Check Environment reports whether it is installed without failing on its absence.
- **Journal:** one JSONL file per run under the extension's global storage (`journal/<slug>-<UTC stamp>.jsonl`), never inside the worktree; the first record names the chain. Your chat messages (`you`) and answers (`answer`) are recorded with the card they went to.

## 2026-10-22 — fix: Close git guard gaps and keep tool input values out of the journal

- **Git guard, plumbing and outward commands:** `HARD` in `src/guard.ts` gains `update-index`, `commit-tree`, `read-tree` and `checkout-index`. They slipped past before because the boundary after `commit` or `checkout` rejects a `-`. It also gains `send-email` and `imap-send`, which send patches out. `SOFT` gains `reflog expire` / `delete`, `sparse-checkout set` / `add` / `init` / `reapply` / `disable` and `svn dcommit`. `git reflog`, `reflog show`, `sparse-checkout list` and `git svn log` stay open.
- **Git guard, branch flags:** a branch's writing flag (`-d` / `-D` / `-m` / `-M` / `-c` / `-C` / `-f` / `-t` / `-u` and the long forms, `--no-track` and `--set-upstream-to=` included) is denied wherever it sits among the flags, so `git branch -q -f other HEAD` no longer passes. Skipped tokens must start with `-`, so `git branch -vv | sort -u` stays open. A bare name is still caught only right after `branch`: `git branch -q new` gets past, because `--contains X` and `--list pattern` look the same to a text scan. The profile names it as a known gap.
- **Denied-tool log:** `denyTool` (`src/unattended.ts`) logs the tool's name and its input keys, through `plain()` and clipped to 300, instead of the clipped JSON input. The log goes into the run journal, and a denied `Write` or `Bash` input can carry file contents or a credential.
- **Review fixes (same session):** the working-tree review found the branch flags caught only in first position, `-u` and `--no-track` open, and `imap-send` / `svn dcommit` open, each confirmed by running `gitWriteDenial`. All were fixed in this session, each with a test. The review's suggestion to also deny `git branch --quiet new` was dropped for the reason above.
- **Docs:** the profile's §Security rows for unattended session permissions and the git guard describe the new rules and the remaining gap.
- **Tests:** `src/guard.test.ts` gains denied rows for each new rule and allowed rows for the listing forms around them. `src/unattended.test.ts` asserts that keys are logged, values never are (a credentials-file write), and control characters are stripped from keys.
- **Gates:** `pnpm typecheck`, `pnpm test` (514 tests), `pnpm build` and `pnpm audit` (no known vulnerabilities) all passed in this session; `pnpm coverage` was not run. Not checked: a denial inside a real run, which waits on the F5 smoke.
- **Why it matters:** a session can no longer stage or commit through plumbing, move a branch, or mail patches out by accident, and a denied tool call no longer copies what it tried to write into the journal.
- **Affected:** `src/guard.ts`, `src/unattended.ts`, `.claude/PROJECT-PROFILE.md`.

## 2026-10-13 — feat: Talk to a run in the chat

- **Run engine:** `runSessionAt` (`src/run.ts`) gains the pause loop. A card with `pause`, or one the user paused (`pausePending`), waits after each turn in `talk.waitForYou`. A message is the next turn of the same conversation (shown as `<label> · chat`), and **Continue** applies the latest status line the card gave since it started waiting. A pausing card that gave none is done; a paused unattended card that gave none gets the usual one reminder. An unattended `HALT` ends the run even when a pause was asked for. Only unattended turns count toward `MAX_TURNS`. Messages queued during a turn go in front of the next turn's prompt (`takeQueued`), and the last card of a session tells the chat which card a message would reach in the next session (`SessionPlace.nextSession`). `RunDeps.runTurn` now takes `TurnAsk`, which adds `interactive`, and `runnable` no longer refuses chains with a pausing card.
- **Chat state:** `Talk` (`src/talk.ts`) holds one run's chat: phase (`idle` / `running` / `waiting` / `ended`), the card and its index in its session, the queue with **Withdraw**, the pending pause, the open question, and the messages handed back by `end()`. `createRunChat` (`src/run-chat.ts`) wires it to the journal, the transcript and the editor. `forTurn(interactive)` picks `INTERACTIVE_NOTE` and `interactiveCanUseTool`, or `UNATTENDED_NOTE` and `unattendedCanUseTool`, for each turn. `actOnChat` applies the webview's chat messages.
- **Questions and permissions:** `interactiveCanUseTool` (`src/unattended.ts`) sends only AskUserQuestion to the user. Every other tool is denied and logged as in an unattended turn, an unreadable question is denied, and a stop before the answer is a denial. `isQuestion` now also checks the types of `header` and `multiSelect`. `checkAnswers` (`src/chat-logic.ts`) accepts only offered labels, or text marked Other, for the open question's id. `INTERACTIVE_NOTE` (`src/protocol.ts`) tells the skill the user is present, that the chain moves on with Continue, and to keep the same `COORDINER:` status lines.
- **Transcript:** `runTurn` (`src/session.ts`) takes `onMessage` for the conversation's own assistant messages; subagent messages (`parent_tool_use_id` set) are skipped. `entriesFrom` (`src/transcript.ts`) keeps text and tool calls only, through `plain()`. `Transcript` keeps the newest `MAX_ENTRIES` (1000), with one marker at the top once older entries are dropped. A divider marks each new session.
- **Editor protocol:** six chat messages (`chatSend`, `chatWithdraw`, `chatPause`, `chatContinue`, `chatAnswer`, `chatStop`), each with an exact key set. `chatSend` must be non-empty and at most `MAX_INPUT_CHARS`, which moved from `src/run.ts` to `src/chains.ts`. `chatAnswer` carries 1–4 picks of labels of up to 1000 characters each. The chat goes to the webview as its own `ChatMessage` (`chat` / `chatAppend` / `chatUpdate`), apart from the chains state, so a new message never re-renders the chain being edited. `EditorState.runningAt` is `{ chainId, session, index }`: the card is matched by index because two cards in a session can share a label.
- **Extension:** `RunState` keeps the chat after the run ends, so the last transcript stays until the next run starts. When a card starts waiting or asks something, `needsYou` opens the editor with `preserveFocus`, and shows a notification only when the editor was not in view. Chat messages with no run going are ignored and logged. The confirm dialog no longer calls the run "unattended", and says which cards wait in the chat.
- **Webview:** `media/chat.js` builds the chat once and updates it in place, so the message box is never replaced while you type. It covers the transcript, the queue, the question form, **Send** / **Pause after this turn** / **Continue to …** / **Stop run**, and status announcements chosen in `src/chat-logic.ts`. The divider above it is a focusable window-splitter (drag, or ↑/↓/Home/End in 5% steps between 15% and 80%, 35% to start). `media/editor.js` and `media/chat.js` write the shared webview state through `remember`, which merges. The running card shows a **Running** flag and `aria-current="step"`, drawn with an inset shadow so the lane does not shift. `typing()` ignores the chat's own fields.

## 2026-10-10 — feat: Session two and the run journal (slice 2)

- `runStorySession` became `runSession(script, deps)`, driven by a `Script` (`open` turn, `work` loop on `NEXT`, optional `close` turn on `DONE`). `sessionOne(story)` is plan → implement; `SESSION_TWO` is review → fix → history. A `NEXT` in the closing turn counts as a missing status line (one reminder, then halt).
- `runStory` runs session 1, then `prepareReview`, then session 2 as a **fresh** session (never a resume) so the reviewer does not share the author's context. Step numbers continue across both sessions.
- `prepareReview` (`src/worktree.ts`): `git status --porcelain` → `no-changes` on a clean tree; otherwise NUL-separated `ls-files --others --exclude-standard` and `git --literal-pathspecs add --intent-to-add -- …`, so new files appear in `git diff HEAD` without staging their content. More than 200 new files halts the run (usually a missing `.gitignore` entry). `--literal-pathspecs` stops a model-chosen name like `:!src/x.ts` from excluding another file from the review.
- `Outcome`: `done` carries the commit brief text (status line stripped by `withoutStatus`); new `no-changes`; `halted` carries `sessionId`; a halt or failure before the review sets `beforeReview`. `remainingCommands(outcome, labels)` lists what is left to run by hand.
- `UNATTENDED_NOTE` tells the review, fix and history phases how to end.
- Journal (`src/journal.ts`): `createJournal` writes one JSON line per record in call order; a failed write is reported once and never stops the run.
- **Why it matters:** a story now runs unattended all the way to a reviewed, fixed change and a commit brief, and every run leaves a record you can read afterwards.
- **Affected:** `src/run.ts`, `src/protocol.ts`, `src/worktree.ts`, `src/journal.ts`, `src/extension.ts`, `.claude/PROJECT-PROFILE.md`.
