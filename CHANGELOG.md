# Changelog

Newest entry first. The **Current state** section describes the extension as it is now, not how it got here.

## Current state (last synced 2026-10-13)

- **Commands:** `Coordiner: Check Environment`, `Coordiner: Run Story…` (runs the Story template), `Coordiner: Open Chains`, `Coordiner: Stop Run`; a Run view in the activity bar lists each step with its tier, model and status, with a button in its title bar for the chains editor.
- **Chains:** a chain is a list of sessions, each a row of skill cards (`skill`, `args`, `label`, `pause`, optional `next`). Every session is a fresh conversation. Four read-only templates ship, named after what you bring: Story, Idea (brainstorming → planning → implementing), Bug (debugging alone, which writes the fix itself) and New project (kickoff → planning → implementing); a template is duplicated to edit, and your own chains are saved in `chains.json` in the extension's global storage, never in a repo. A placeholder in a card's arguments sets what Run asks for: `{{story}}` a backlog story or a typed one, `{{idea}}` and `{{bug}}` a typed answer. A chain uses one kind at most (Run refuses more); a chain with none asks only for a run name.
- **Chains editor:** a webview (`Coordiner: Open Chains`) with templates and saved chains on the left and the selected chain's sessions on the right, a "fresh context" divider between sessions. Cards are added from the skills the open folder's Claude Code session offers (listed once per window without a model turn; m-skills first), moved with arrow buttons or Alt+←/→, and edited in place; every change is saved at once. Each chain says what it starts from; a placeholder shows as a chip with what Run will put there, and an editable chain explains the three placeholders. A disabled Run says why. A `chains.json` that cannot be read is set aside as `chains.json.bak-<time>` and the editor says so.
- **Run:** asks for the chain's input. A story is picked from a Markdown backlog file (`## Story N: …` / `### Slice N: …` headings) or typed via **Type a story…**; an idea or a bug is typed. A typed answer suggests the run name (its slug, or an empty name when it has no letter or digit in `[a-z0-9]`), which you can change; a picked story is named by its heading. The input is capped at 20,000 characters (heading and body together for a picked story). A chain without a placeholder asks only for a name. A modal confirm lists each session's cards, then a worktree is created at `<repo>.coordiner/<slug>` on branch `coordiner/<slug>` from `HEAD`, and the lockfile-derived install command runs in it.
- **Card semantics:** a "once" card takes one turn; `NEXT <tier>` moves to the next card on that tier, `DONE` moves on at the card's own tier. The implementing card is a "loop": it continues on each `NEXT` (tier stops: Heavy/Standard/Light → strong/medium/weak) until `DONE`. A review's `DONE` skips the loop cards after it. A card that pauses for the user (brainstorming, debugging, kickoff), or one the user paused, talks with them in the run's chat: after each turn it waits, each message is another turn, and **Continue** applies the latest status line it gave (a pausing card that gave none is done). Only unattended turns count toward the 20-turn cap.
- **Story template:** session 1 is `planning-architect` → `implementing-architect`; session 2 starts with new files marked intent-to-add (literal pathspecs, cap 200), then `code-review-architect-uncommitted` → `implementing-architect fix the findings` → `rolling-history`. The commit brief is shown in the Coordiner output; nothing is committed.
- **Run chat:** a strip under the chains editor, tied to the run rather than to the selected chain (`media/chat.js`, decisions in `src/chat-logic.ts`, state in `src/talk.ts`, transcript in `src/transcript.ts`, its wiring to the editor and the journal in `src/run-chat.ts`). A divider above it (a focusable separator: drag, or ↑/↓/Home/End) sets its height, 15–80% of the window, remembered in the webview's state; **Hide chat** folds it to its heading. It shows assistant text and tool calls as plain text, your messages and answers, and a divider between sessions; the running card is marked in its lane. **Send** queues a message in front of the next turn's prompt, with its destination shown and **Withdraw**; **Pause after this turn** makes an unattended card wait; a skill's AskUserQuestion during a pause is answered in a form (offered labels or Other); **Stop run** stops it. A pause or question while the editor is closed opens it without taking focus, with a notification; an open question has no time limit. Queued messages left when the run ends go back to the message box. Paused turns get `INTERACTIVE_NOTE` instead of `UNATTENDED_NOTE`.
- **Stops:** a halt or failure prints the `claude --resume` line for the session; a stop after the first session also lists the card prompts left to run by hand, from the card that stopped. A run whose review session finds no changed file ends as "nothing to review".
- **Git guard:** every session carries coordiner's own PreToolUse hook on Bash (`src/guard.ts`): git writes, `--no-verify` / `--no-gpg-sign` and publishing `gh` commands are denied whichever skills the chain uses, and an unreadable command or a hook error is a denial. Denials are logged without the command text.
- **Unattended rules:** permission mode `auto`, questions take the Recommended option and are logged (in a paused turn they go to the user instead; every other tool is still decided as unattended). A turn is refused if a skill the chain uses is missing from the session, if a chain using m-skills reports an m-skills load error, or if the model differs from the one requested; each session is capped at 20 turns. m-skills is recommended, not required; Check Environment reports whether it is installed without failing on its absence.
- **Journal:** one JSONL file per run under the extension's global storage (`journal/<slug>-<UTC stamp>.jsonl`), never inside the worktree; the first record names the chain. Your chat messages (`you`) and answers (`answer`) are recorded with the card they went to.

## 2026-10-13 — feat: Talk to a run in the chat

- **Run engine:** `runSessionAt` (`src/run.ts`) gains the pause loop. A card with `pause`, or one the user paused (`pausePending`), waits after each turn in `talk.waitForYou`. A message is the next turn of the same conversation (shown as `<label> · chat`), and **Continue** applies the latest status line the card gave since it started waiting. A pausing card that gave none is done; a paused unattended card that gave none gets the usual one reminder. An unattended `HALT` ends the run even when a pause was asked for. Only unattended turns count toward `MAX_TURNS`. Messages queued during a turn go in front of the next turn's prompt (`takeQueued`), and the last card of a session tells the chat which card a message would reach in the next session (`SessionPlace.nextSession`). `RunDeps.runTurn` now takes `TurnAsk`, which adds `interactive`, and `runnable` no longer refuses chains with a pausing card.
- **Chat state:** `Talk` (`src/talk.ts`) holds one run's chat: phase (`idle` / `running` / `waiting` / `ended`), the card and its index in its session, the queue with **Withdraw**, the pending pause, the open question, and the messages handed back by `end()`. `createRunChat` (`src/run-chat.ts`) wires it to the journal, the transcript and the editor. `forTurn(interactive)` picks `INTERACTIVE_NOTE` and `interactiveCanUseTool`, or `UNATTENDED_NOTE` and `unattendedCanUseTool`, for each turn. `actOnChat` applies the webview's chat messages.
- **Questions and permissions:** `interactiveCanUseTool` (`src/unattended.ts`) sends only AskUserQuestion to the user. Every other tool is denied and logged as in an unattended turn, an unreadable question is denied, and a stop before the answer is a denial. `isQuestion` now also checks the types of `header` and `multiSelect`. `checkAnswers` (`src/chat-logic.ts`) accepts only offered labels, or text marked Other, for the open question's id. `INTERACTIVE_NOTE` (`src/protocol.ts`) tells the skill the user is present, that the chain moves on with Continue, and to keep the same `COORDINER:` status lines.
- **Transcript:** `runTurn` (`src/session.ts`) takes `onMessage` for the conversation's own assistant messages; subagent messages (`parent_tool_use_id` set) are skipped. `entriesFrom` (`src/transcript.ts`) keeps text and tool calls only, through `plain()`. `Transcript` keeps the newest `MAX_ENTRIES` (1000), with one marker at the top once older entries are dropped. A divider marks each new session.
- **Editor protocol:** six chat messages (`chatSend`, `chatWithdraw`, `chatPause`, `chatContinue`, `chatAnswer`, `chatStop`), each with an exact key set. `chatSend` must be non-empty and at most `MAX_INPUT_CHARS`, which moved from `src/run.ts` to `src/chains.ts`. `chatAnswer` carries 1–4 picks of labels of up to 1000 characters each. The chat goes to the webview as its own `ChatMessage` (`chat` / `chatAppend` / `chatUpdate`), apart from the chains state, so a new message never re-renders the chain being edited. `EditorState.runningAt` is `{ chainId, session, index }`: the card is matched by index because two cards in a session can share a label.
- **Extension:** `RunState` keeps the chat after the run ends, so the last transcript stays until the next run starts. When a card starts waiting or asks something, `needsYou` opens the editor with `preserveFocus`, and shows a notification only when the editor was not in view. Chat messages with no run going are ignored and logged. The confirm dialog no longer calls the run "unattended", and says which cards wait in the chat.
- **Webview:** `media/chat.js` builds the chat once and updates it in place, so the message box is never replaced while you type. It covers the transcript, the queue, the question form, **Send** / **Pause after this turn** / **Continue to …** / **Stop run**, and status announcements chosen in `src/chat-logic.ts`. The divider above it is a focusable window-splitter (drag, or ↑/↓/Home/End in 5% steps between 15% and 80%, 35% to start). `media/editor.js` and `media/chat.js` write the shared webview state through `remember`, which merges. The running card shows a **Running** flag and `aria-current="step"`, drawn with an inset shadow so the lane does not shift. `typing()` ignores the chat's own fields.
- **Journal:** `you` and `answer` records, each with the card it went to.
- **Review fixes (same session):** the running card is keyed by index rather than label (`Talk.at` takes `index`, and `moved()` compares it). The profile's seam rule names `src/chat-logic.ts`, and its design-system, test-layer and placement lines name `media/chat.js` and `src/chat-dom.test.ts`. The running card's second border pixel is a shadow.
- **Tests:** `src/chat-dom.test.ts` runs the real `media/editor.js` and `media/chat.js` in jsdom; new unit suites are `src/talk.test.ts`, `src/run-chat.test.ts`, `src/transcript.test.ts` and `src/chat-logic.test.ts`. `src/run.test.ts` covers pause, chat, Continue, the cap exemption, a stop while waiting, and queueing across the fresh-context divider.
- **Docs:** README has "Talk to a run in the chat", and the ⏸ note no longer says those templates cannot run. The profile's §Security controls, blind spots, direction brief and §Recurring Propagation Sites cover the chat.
- **Gates:** `pnpm typecheck`, `pnpm test` (428 tests), `pnpm coverage` (100% lines, branches and functions), `pnpm build` and `pnpm audit` (no known vulnerabilities) all passed in this session. Not checked: the round trip with the real SDK, the editor opening on a pause, dragging the divider, and the chat's layout, themes and screen-reader speech, which wait on the F5 smoke.
- **Why it matters:** the brainstorm, debugging and kickoff templates can run now, and any running card can be steered, paused or asked a follow-up from the editor, without dropping to `claude --resume`.
- **Affected:** `src/run.ts`, `src/talk.ts`, `src/run-chat.ts`, `src/chat-logic.ts`, `src/transcript.ts`, `src/unattended.ts`, `src/protocol.ts`, `src/session.ts`, `src/journal.ts`, `src/chains.ts`, `src/editor-protocol.ts`, `src/editor-logic.ts`, `src/editor-html.ts`, `src/extension.ts`, `media/chat.js`, `media/editor.js`, `media/editor.css`, `README.md`, `.claude/PROJECT-PROFILE.md`.

## 2026-10-12 — feat: Start a chain from a story, an idea or a bug

- **Inputs:** `INPUTS` in `src/chains.ts` defines three placeholders, `{{story}}`, `{{idea}}` and `{{bug}}`, each with the question Run asks, the chip text and the "starts from" line. `inputKinds(chain)` lists the kinds a chain uses and `inputOf(chain)` returns the first; `runnable` refuses a chain that uses more than one, since Run asks for one input. `STORY` and `usesStory` are gone.
- **Templates:** renamed after what you bring, with new ids: `brainstorm-story` → `idea` ("Idea"), `debug-story` → `bug` ("Bug"), `kickoff` → `new-project` ("New project"). Idea and New project take `{{idea}}`, Bug takes `{{bug}}`. Bug's first session is now `debugging-architect` alone (it writes the regression test and the fix itself), without the plan and implement cards. A stored editor selection pointing at an old id falls back as for a deleted chain.
- **Run engine:** `fillStory(chain, story)` became `fillInput(chain, text)` (`src/run.ts`): it fills the chain's own placeholder with one `split`/`join` pass, so a placeholder inside the typed text is not substituted again, and returns a chain without a placeholder unchanged. `MAX_STORY_CHARS` became `MAX_INPUT_CHARS` (still 20,000) and now caps the whole text, heading included. `storyText(story)` (`src/backlog.ts`) builds "heading, blank line, body".
- **Asking at Run:** `askInput(kind)` in `src/extension.ts` replaces the story-or-name branch. The backlog quick pick gains a **Type a story…** entry. Typed text is checked for length and emptiness only, so text in any script is accepted; the run name is pre-filled with its slug when it has a letter or digit in `[a-z0-9]` and left empty otherwise, and `nameRun` still validates the name. The `run-started` journal record's `story` field now holds the run name.
- **Chains editor:** `startsFrom(chain)`, `argParts(args)` and `PLACEHOLDER_NOTE` in `src/editor-logic.ts`; `media/editor.js` shows each placeholder in a card's arguments as a `.chip` span (text nodes only, never markup), a `.starts` line under the toolbar, and on an editable chain the note listing the placeholders, built from `INPUT_KINDS` so it cannot drift from them.
- **Docs:** README "Run a story" explains what a story is, shows a fuller backlog example and the **Type a story…** option; "Build and run a chain" has the new template table (what you bring, what Run asks) and a placeholder table.
- **Gates:** `pnpm typecheck`, `pnpm test` (314 tests), `pnpm coverage` (100% lines, branches and functions), `pnpm build` and `pnpm audit` (no known vulnerabilities) all passed in this session. Not checked: the typed-input flow in `src/extension.ts`, which waits on the F5 smoke.
- **Why it matters:** a run no longer needs a written backlog story; you start from whatever you have, a story, a one-line idea or a bug report, and each template says up front what it will ask for.
- **Affected:** `src/chains.ts`, `src/run.ts`, `src/backlog.ts`, `src/extension.ts`, `src/editor-logic.ts`, `media/editor.js`, `media/editor.css`, `README.md`.

## 2026-10-12 — feat: Chains of skills and the chains editor (slice 3)

- **Run engine:** `runStory` / `runSession(script)` / `sessionOne` / `SESSION_TWO` became `runChain(chain, deps)` over `runSessionAt(session)` (`src/run.ts`), driven by cards instead of hard-coded scripts. Per-skill behaviour (kind `once`/`loop`, tier, label, `next` prompt, `doneSkipsLoops`) lives in `SKILL_DEFAULTS` in `src/chains.ts`; any skill not in it is a "once" card on the medium tier. `fillStory` substitutes `{{story}}` and keeps the 20,000-character cap. A session whose first card is the uncommitted review triggers `prepareReview`, so the intent-to-add step follows the chain rather than a fixed "session 2".
- **Outcome shape:** `beforeReview` is replaced by `at: { session, card }` on `halted` / `failed`. `remainingCommands(chain, outcome)` lists the card prompts from the stopped card onward for a stop after session 1, and nothing for a stop inside session 1 (taken over with `claude --resume`). `JournalRecord` `run-started` gained `chain`, so the journal format changed.
- **Chain storage:** `Chain` / `Card` in `src/chains.ts`, with `parseChains` / `serializeChains` (`version: 1`). Parsing rebuilds each field into a fresh object, so unknown keys, including `__proto__`, never survive; skill names must match `^[A-Za-z0-9:_.-]{1,100}$`; template ids are reserved; limits of 20 sessions, 30 cards, 20,000 characters of args. `src/extension.ts` writes through a temp file and rename, sets a bad file aside as `chains.json.bak-<time>`, and refuses to save while an unreadable file could not be moved aside.
- **Skill discovery:** `listCommands` (`src/session.ts`) opens an SDK query whose prompt stream never sends a message, reads `supportedCommands()` from the initialize answer and aborts the session, so no model turn is spent (60-second timeout). `palette` (`src/skills.ts`) lists m-skills first, then the rest alphabetically.
- **Skill checks:** `runTurn` takes `requiredCommands` and `pluginProblem(init, required)` refuses a turn when a needed skill is absent; the m-skills load-error check applies only to chains that use m-skills. `REQUIRED_COMMANDS` now only defines "m-skills installed" for the editor and Check Environment.
- **Git guard:** `src/guard.ts` ports the rules of the m-skills `guard-mutations.sh` and `guard-outward.sh` into a PreToolUse hook that `runTurn` attaches to every session, because the plugin's own hook is no longer guaranteed to be loaded. It scans the whole command string with a lookbehind (so `/usr/bin/git` matches without a quadratic scan), allows the listing forms of `branch`, `tag`, `remote`, `stash` and `worktree`, and fails closed. Known gaps: a quoted mention such as `echo "git commit"` is denied; a command built at run time (`g=git; $g commit`) is not caught.
- **Webview:** the editor is plain DOM (`media/editor.js`, `media/editor.css`, native elements, `--vscode-*` variables only). `src/editor-html.ts` builds the page with a nonce CSP; `src/editor-protocol.ts` accepts only messages with an exact key set per type and rebuilds a `save` payload through `parseChain`; the m-skills link is a constant. Decisions (why Run is disabled, missing-skill flag, focus after a move or remove, Alt+arrow) live in `src/editor-logic.ts` and edits in `src/chain-edit.ts`, so `media/editor.js` only builds the DOM; `chains.ts`, `chain-edit.ts` and `editor-logic.ts` also load in the webview from `dist/`, so they import nothing at runtime beyond each other.
- **Tests:** webview DOM tests run the real `media/editor.js` in jsdom (`src/editor-dom.test.ts`); `jsdom` and `@types/jsdom` joined the exact-pinned dev dependencies, and `pnpm coverage` now includes `media/**/*.js`.
- **Docs and prompts:** `UNATTENDED_NOTE` says "a chain of skills" and tells any other skill to end with `COORDINER: DONE`. README prerequisites now call m-skills recommended, the pnpm prerequisite reads pnpm 12 to match `packageManager`, and a "Build and run a chain" section was added. Check Environment reports m-skills as information only.
- **Gates:** not run in this session; this entry records the diff.
- **Why it matters:** the story flow is now one template among several, so you can build and run your own chains of skills, with the no-commit and no-publish promise enforced by coordiner itself rather than by whichever plugin happens to be installed.
- **Affected:** `src/chains.ts`, `src/chain-edit.ts`, `src/run.ts`, `src/session.ts`, `src/skills.ts`, `src/guard.ts`, `src/protocol.ts`, `src/environment.ts`, `src/journal.ts`, `src/extension.ts`, `src/editor-html.ts`, `src/editor-logic.ts`, `src/editor-protocol.ts`, `media/editor.js`, `media/editor.css`, `package.json`, `pnpm-lock.yaml`, `README.md`, `.claude/PROJECT-PROFILE.md`.

## 2026-10-10 — feat: Session two and the run journal (slice 2)

- `runStorySession` became `runSession(script, deps)`, driven by a `Script` (`open` turn, `work` loop on `NEXT`, optional `close` turn on `DONE`). `sessionOne(story)` is plan → implement; `SESSION_TWO` is review → fix → history. A `NEXT` in the closing turn counts as a missing status line (one reminder, then halt).
- `runStory` runs session 1, then `prepareReview`, then session 2 as a **fresh** session (never a resume) so the reviewer does not share the author's context. Step numbers continue across both sessions.
- `prepareReview` (`src/worktree.ts`): `git status --porcelain` → `no-changes` on a clean tree; otherwise NUL-separated `ls-files --others --exclude-standard` and `git --literal-pathspecs add --intent-to-add -- …`, so new files appear in `git diff HEAD` without staging their content. More than 200 new files halts the run (usually a missing `.gitignore` entry). `--literal-pathspecs` stops a model-chosen name like `:!src/x.ts` from excluding another file from the review.
- `Outcome`: `done` carries the commit brief text (status line stripped by `withoutStatus`); new `no-changes`; `halted` carries `sessionId`; a halt or failure before the review sets `beforeReview`. `remainingCommands(outcome, labels)` lists what is left to run by hand.
- `UNATTENDED_NOTE` tells the review, fix and history phases how to end.
- Journal (`src/journal.ts`): `createJournal` writes one JSON line per record in call order; a failed write is reported once and never stops the run.
- **Why it matters:** a story now runs unattended all the way to a reviewed, fixed change and a commit brief, and every run leaves a record you can read afterwards.
- **Affected:** `src/run.ts`, `src/protocol.ts`, `src/worktree.ts`, `src/journal.ts`, `src/extension.ts`, `.claude/PROJECT-PROFILE.md`.
